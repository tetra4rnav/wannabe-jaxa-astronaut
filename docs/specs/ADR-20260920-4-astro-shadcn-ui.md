# ADR-20260920-4 — Astro + shadcn UI

**Status:** accepted  
**Date:** 2026-09-20

## Context

The public site mixed Astro Starlight chrome (`data-theme`, docs sidebar, splash home) with shadcn/ui islands. Light/dark did not flip as a whole page. The home splash hid the wiki sidebar. Starlight’s desktop sidebar cannot collapse without replacing `PageFrame`.

## Decision

- Public UI is **Astro layouts + shadcn/ui**. Do not use Starlight.
- Theme follows the shadcn Astro guide: light tokens on `:root`, dark tokens on `.dark`, inline script + `ModeToggle`. Do not add `next-themes`.
- Home (`/`) is the live news feed (`/news.json`). `/news/` redirects to `/`.
- Navigation is a collapsible shadcn-style sidebar (desktop hide/show, mobile overlay).
- Wiki canon stays human Markdown under `src/content/docs/`. HTML is generated from the Astro content collection.

## Consequences

- Pagefind search and Starlight asides are gone until reintroduced on purpose.
- `/llms.txt` (and compact/full variants) are generated by Astro endpoints, not `starlight-llms-txt`.
- [ADR-20260920-1](./ADR-20260920-1-pages-and-worker.md) still owns Pages vs Worker; this ADR owns the UI stack.

## Alternatives considered

- Keep Starlight and bridge shadcn to `data-theme` — rejected; dual tokens were the theme bug.
- Drop shadcn and stay on Starlight — rejected; home-as-feed and a collapsible desktop sidebar fit shadcn.
