# ADR-20260920-4 — Astro + shadcn UI

**Status:** accepted  
**Date:** 2026-09-20

## Context

The public site mixed Astro Starlight chrome (`data-theme`, docs sidebar, splash home) with shadcn/ui islands. Light/dark did not flip as a whole page. The home splash hid the wiki sidebar. Starlight’s desktop sidebar cannot collapse without replacing `PageFrame`.

## Decision

- Public UI is **Astro layouts + shadcn/ui**. Do not use Starlight.
- Theme follows the shadcn Astro guide: light tokens on `:root`, dark tokens on `.dark`, inline script + `ModeToggle`. Do not add `next-themes`. Brand palette: PANTONE 293 / Cool Gray 10 / navy (screen approx.); header inverts by theme.
- Home (`/`) shows a short news excerpt plus Wiki theme cards. Full feed and filters live at `/news/`.
- Navigation is a collapsible sidebar panel (desktop hide/show, mobile overlay) with in-sidebar group accordion and a nav title search.
- Wiki canon stays human Markdown under `src/content/docs/`. HTML is generated from the Astro content collection (`prerender` where static).

## Consequences

- Pagefind full-text search is not restored; sidebar search filters nav titles only.
- `/llms.txt` (and compact/full variants) are generated by Astro endpoints, not `starlight-llms-txt`.
- [ADR-20260920-1](./ADR-20260920-1-pages-and-worker.md) / [ADR-20260920-5](./ADR-20260920-5-astro-ssr-pages.md) own Pages vs Worker and SSR; this ADR owns the UI stack.

## Alternatives considered

- Keep Starlight and bridge shadcn to `data-theme` — rejected; dual tokens were the theme bug.
- Drop shadcn and stay on Starlight — rejected; home layout and a collapsible desktop sidebar fit shadcn.
